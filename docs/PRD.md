# 产品需求文档

## 基本要求

- 这是一个设备序列号的管理软件，负责生成和查询特定格式的设备序列号。
- 使用 Python 开发，使用 uv 做项目管理；开发可在 Linux 上进行。
- **运行环境**：Windows 或 Linux 单机；Windows 可执行文件由 GitHub Actions（PyInstaller）发布，Linux 可执行文件由本地 PyInstaller 脚本构建。
- **使用场景**：产线单机桌面工具。操作员在本机生成 / 查询 SN，数据存在本机，不必联网。
- **交互形态**：图形界面（GUI），中文界面，无登录。

## 设备序列号的格式

设备序列号（SN）是一个字符串，字符串的第一个字符是设备序列号的格式的版本号，决定了 SN 的长度和格式。支持的版本如下。

### Version A

Version A 的设备序列号，长度固定17个字符，占用17个字节，包含数字和字母，所有字母都是大写。格式如下：

| **字符** | **示例值** | **说明**                                                     |
| -------- | ---------- | ------------------------------------------------------------ |
| 1        | A          | SN格式的版本：一个字符，大写字母，从A开始                             |
| 2~6      | SVG14      | 产品型号：五个字符，字母或者数字，对外销售的统一型号                  |
| 7~8      | 01         | 硬件批次：两个字符，字母或者数字，同一个产品的不同批次可能有硬件差异  |
| 9        | 1、2       | 生产单位：一个字符，字母或者数字，自己生产为1，赛威思生产为2          |
| 10       | 0、1、2、3 | 投放的市场：一个字符，字母或者数字，0表示不限，1表示中国，2表示韩国，3表示美国等 |
| 11~12    | 26、27     | 生产年：两个字符，两个数字，26表示2026年                              |
| 13       | 1~C        | 生产月：一个字符，1表示1月，9表示9月，A表示10月，B表示11月，C表示12月 |
| 14       | 1~V        | 生产日：一个字符，1表示1日，9表示9日，A表示10日，U表示30日，V表示31日 |
| 15~17    | 000~FFF    | 设备序号：三个字符，十六进制数，当日生产的同一个产品（当日+产品型号+硬件批次）的设备序号。 |

实例： **ASVG140521261CF04**

| **位置** | **值** | **说明**     |
| -------- | ------ | ------------ |
| 1        | A      | SN版本       |
| 2~6      | SVG14  | 产品型号     |
| 7~8      | 05     | 硬件批次     |
| 9        | 2      | 赛威思生产   |
| 10       | 1      | 中国市场     |
| 11~12    | 26     | 2026年       |
| 13       | 1      | 1月          |
| 14       | C      | 12日         |
| 15~17    | F04    | 当日第3844台 |

首期只实现 Version A；版本号字符预留后续扩展。

## 技术方案

### 选型

- **方案**：桌面 GUI（PySide6）+ 本地 SQLite + 领域核心库；用 **PyInstaller** 打包：Windows 经 CI 产出 onedir zip，Linux 经本地脚本产出 onedir
- **开发**：Python（≥3.12）+ uv（可在 Linux 上开发）
- **打包约束**：PyInstaller 一般需在**目标操作系统上**构建（或在对应系统的 CI 中构建），不依赖不可靠的交叉编译

### 分层（单向依赖）

```
sn_gui (PySide6)
    → sn_app（应用服务：事务编排、批量生成、导出并可选改状态）
        → sn_core（SN 编解码 / 校验 / 状态规则）
        → sn_db（SQLite 持久化与序号分配）
```

### 运行约定

- 数据文件：与可执行文件同目录的单文件 SQLite：`sn_manager.db`（Windows / Linux 相同策略）
- 无登录、无网络依赖
- 便于整库备份 `sn_manager.db`

## 数据库设计

单库 `sn_manager.db`。

### 主数据表

| 表 | 关键字段 | 说明 |
| ---- | ---------- | ------ |
| `product_models` | `code` CHAR(5) UNIQUE, `name` | 产品型号，如 SVG14 / 名称说明含义（非空，≤64） |
| `hardware_batches` | `(product_model, code)` 联合主键, `name` | 硬件批次从属于型号；同码可在不同型号下含义不同（非空，≤64） |
| `factories` | `code` CHAR(1) UNIQUE, `name` | 生产单位，如 1/自己、2/赛威思；名称 ≤64 |
| `markets` | `code` CHAR(1) UNIQUE, `name` | 市场，如 0/不限、1/中国；名称 ≤64 |

首次启动可写入常见 `factories` / `markets` 种子数据；型号及其下属批次由用户在主数据对话框维护。名称均必填、去首尾空白后非空、长度不超过 64。

### SN 记录表 `serial_numbers`

| 字段 | 说明 |
| ---- | ------ |
| `sn` TEXT UNIQUE | 完整 17 位 SN |
| `version`, `product_model`, `hw_batch`, `factory`, `market` | 解析字段，便于筛选 |
| `prod_year`, `prod_month`, `prod_day` | 公历数值（如 2026, 12, 1）；写入 SN 时再编码为两位年与月日字符 |
| `seq` INTEGER | 当日序号 0–4095（对应 `000`–`FFF`） |
| `status` | `unused` / `used` / `void`，三种可任意互改 |
| `created_at`, `updated_at` | UTC ISO-8601 文本 |

**唯一性约束**：`(product_model, hw_batch, prod_year, prod_month, prod_day, seq)` 唯一，对应「当日 + 产品型号 + 硬件批次」维度。

### 序号分配

不单独维护计数器表：同一事务内对该维度取 `MAX(seq)+1` 起连续分配。若将超过 4095（`FFF`），整批失败回滚。作废不删行、**不回收** `seq`。

## 软件功能

### 1. 主数据维护

- 维护产品型号（及其下属硬件批次）、生产单位、市场（增删改查；编码格式校验；名称必填且 ≤64）
- 主数据对话框三个页签：**型号**、**单位**、**市场**；在「型号」页选中型号后，于下方维护该型号的批次（同码可在不同型号下含义不同）
- 三类主数据**仅**在「主数据」对话框中维护；生成与筛选只能从已有主数据下拉选择，不可临时新增
- 删除规则：型号下仍有批次时不可删该型号；批次若已被 SN 以同型号+批次引用则不可删；型号无下属批次且未被 SN 引用才可删
- 对话框 **确认** 后修改生效并回主界面；**取消** 则不生效并关闭

### 2. 生成 SN

- 主界面点「生成」弹出对话框；**下拉选择**：版本(A)、型号、批次、生产单位、市场；另选生产日期（**默认当天，允许修改**）、**数量 N（≥1）**
- 须先选型号，批次下拉仅列出该型号下已维护的批次；切换型号时清空并刷新批次
- **N=1 即生成单个 SN；N>1 为批量**，统一入口
- 一次事务连续分配 `seq` 并写入；新记录状态默认 `unused`；写入前校验所选批次属于该型号
- 若当日该型号+批次剩余序号不足 N：整批回滚，提示更换生产日期或硬件批次
- 对话框 **确认** 后生成并关闭，主界面右侧**仅展示本批**新 SN（默认选中）；**取消** 不生成并关闭
- 生产日期须为真实公历日期；主数据为空或未选齐时提示先维护主数据

### 3. 查询

- 主界面即为查询界面：左侧筛选条件中，型号、批次、生产单位、市场**仅能下拉选择**（首项为空表示不限）；另可填日期范围、状态、完整 SN 等，点「查询」后右侧显示结果
- 型号为「不限」时批次不可用；选了型号后批次列出该型号下项（批次首项仍可为空表示该型号下批次不限）；型号变更时清空批次选择
- 右侧结果表支持多选；**全选** = 选中当前结果表全部行

### 4. 状态管理

每个 SN 三种状态：**未使用（unused）**、**已使用（used）**、**作废（void）**。

- 三种状态可任意互改
- 作废记录仍留在库中可查（含筛选）；选中后仍可导出；序号不回收
- 在右侧选中若干行后，点 **改状态** 选择目标状态
- 导出时可勾选「导出后标为已使用」（仅勾选的导出类型**全部写成功**后再批量更新；任一失败则不改状态）

### 5. 导出

- 须先在右侧 **选中若干行**（可用「全选」）；无选中时「改状态」「导出」均禁用
- 点「导出」弹出对话框：
  - **烧写文本**、**导出 Excel** 为复选框，可多选；界面顺序烧写在上、Excel 在下；默认仅勾选烧写；至少勾选一种
  - 共用「导出路径」（目录）+ 浏览；默认路径为可执行文件所在目录（开发未打包时为当前工作目录）
  - 「导出后标为已使用」默认勾选，可取消
- **烧写文本**：每个选中 SN 在导出目录下写一个文件 `sn_<设备序列号>.txt`，内容仅一行该序列号；同名文件已存在则覆盖
- **Excel**：在导出目录下写一个 `.xlsx`，文件名为本地时间 `YYYYMMDDHHmmss.xlsx`（例：`20260731152950.xlsx`）；含 SN、解析字段、状态、时间

### 6. 界面布局

- **启动后主界面 = 查询界面**
- **左侧**：筛选条件；其下依次为按钮 **查询**、**生成**、**主数据**
- **右侧**：查询/生成结果表；提供 **全选**；**右下角**依次为 **改状态**、**导出**（均须选中行才可点）
- **生成**、**主数据** 以模态对话框完成；主数据对话框内修改须确认才落库，取消则全部放弃


### 7. 非功能（首期）

- 中文 GUI；本机 SQLite；无登录、断网可用
- Windows / Linux 可执行文件均由 PyInstaller 生成
- 数据路径在各平台固定可预期，便于备份 `sn_manager.db`

## 关键流程与异常（摘要）

1. 生成：校验格式 → 事务分配序号并插入 → 触顶则整批回滚并提示改日期/批次
2. 改状态：更新 `status` 与 `updated_at`，不修改 `seq`
3. 导出：仅针对选中行；按勾选写出烧写 txt 与/或 Excel；全部成功后再按选项批量标 `used`；任一写失败则不改状态（已写出的文件可保留）
4. 库无法打开、非法 SN 输入等给出明确中文错误提示

## 测试要点（摘要）

- Version A 编解码往返、非法字段拒绝、序号连续与触顶、N=1/N>1、作废不回收
- 主数据对话框确认/取消；选中行改状态；导出可多选烧写/Excel、共用导出目录、默认 mark used、双选时失败不改状态
- Windows：从 Release / Actions artifact 获取 zip 后启动与读写库文件的手工验证；Linux：本地打包后同等验证
- 界面：启动为查询主界面；无选中时导出禁用；生成成功后右侧展示新 SN
