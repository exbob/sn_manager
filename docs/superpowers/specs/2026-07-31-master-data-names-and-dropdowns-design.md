# 主数据名称与下拉筛选设计

日期：2026-07-31  
状态：已确认  
关联：修订 `docs/PRD.md` 主数据与筛选/生成相关条款；触及 `schema`、`master_data`、`SnService`、`MasterDataDialog`、`GenerateDialog`、`MainWindow`

## 1. 背景与目标

当前产品型号、硬件批次仅有编码，缺少含义说明；单位与市场已有名称。筛选条件中型号/批次/单位/市场为自由文本，生成对话框还允许临时新增型号/批次并写入主数据。

**目标**

1. 四类主数据均维护「编码 + 名称」，名称说明编码含义
2. 筛选与生成中，型号/批次/单位/市场仅能从主数据下拉选择，不能自行添加
3. 主数据是唯一编辑入口

**成功标准**

- 型号、批次表含必填 `name`（≤64）
- 主数据四个 Tab 均为编码 + 名称两列
- 主界面筛选四项为不可编辑下拉；空选项表示不限
- 生成对话框四项为不可编辑下拉；不再自动写入主数据
- PRD 与实现一致；开发期不兼容旧库（删库重建）

## 2. 数据模型

| 表 | 字段 |
| ---- | ---- |
| `product_models` | `code` TEXT PRIMARY KEY（5 位字母数字）+ `name` TEXT NOT NULL |
| `hardware_batches` | `code` TEXT PRIMARY KEY（2 位字母数字）+ `name` TEXT NOT NULL |
| `factories` | `code` TEXT PRIMARY KEY（1 位）+ `name` TEXT NOT NULL（已有） |
| `markets` | `code` TEXT PRIMARY KEY（1 位）+ `name` TEXT NOT NULL（已有） |

名称规则（四类共用）：

- 必填；去首尾空白后非空
- 长度 ≤ 64（按 Unicode 字符计）
- 不做字符集限制（可中文、空格等）
- 不参与 SN 编解码；仅展示与说明

`MasterSnapshot`：`product_models` / `hardware_batches` 由 `list[str]` 改为 `list[tuple[str, str]]`，与 factories / markets 一致。

upsert API：型号/批次写入改为 `(code, name)`；校验名称的公共函数（非空 + ≤64）在 db/服务层统一调用。

**迁移**：不做。直接改 DDL；已有 `sn_manager.db` 需删除重建。

## 3. 界面与交互

### 3.1 主数据对话框

- 四个 Tab 均为两列表格：「编码」「名称」
- 确认时：编码格式校验、名称非空且 ≤64、编码不重复
- 删除规则不变：编码已被 SN 引用则拒绝删除

### 3.2 筛选条件（主界面）

- 「型号 / 批次 / 单位 / 市场」由 `QLineEdit` 改为不可编辑 `QComboBox`
- 展示文案：`编码 名称`（空格分隔）
- 用户数据：编码（`itemData`）；首项为空表示不限
- 主数据对话框确认关闭后，刷新这四个下拉

### 3.3 生成对话框

- 型号、批次去掉 `setEditable(True)`；四项均为不可编辑下拉
- 展示文案同筛选：`编码 名称`
- 未选齐或无可选主数据时提示先维护主数据，不生成
- 服务层去掉生成路径上的 `_ensure_master` 自动插入（调用方不再开启）

## 4. PRD 同步要点

- 主数据表：型号、批次增加 `name`；名称规则（非空、≤64）
- 取消「生成对话框临时新增并保存」；四类仅在主数据对话框维护
- 查询筛选：型号/批次/单位/市场仅下拉
- 生成流程：不再「必要时写入主数据」

同步更新 `2026-07-30-sn-manager-design.md` 中与「临时新增」矛盾的表述。

## 5. 错误与边界

- 名称为空或超过 64：主数据确认时拦截，中文提示
- 生成未选齐 / 列表为空：提示维护主数据
- SN 行上仍只存编码冗余字段；主数据改名称不影响历史 SN 行

## 6. 测试要点

- DB：型号/批次 upsert 带名称；名称超长或空拒绝
- 主数据对话框：四类均收集 `(code, name)`
- 生成对话框：不可编辑；生成不写入主数据表
- 主界面：四项下拉，空选项不参与筛选；确认主数据后选项刷新

## 7. 非目标

- 旧库自动迁移
- 名称写入 SN 或导出格式变更（导出仍用现有字段即可）
- 名称唯一性约束（仅编码唯一）
