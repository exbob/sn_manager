# 查询结果分页与查询中态设计

日期：2026-08-02  
状态：已确认  
关联：`src/sn_manager/db/serials.py`、`src/sn_manager/app/services.py`、`src/sn_manager/gui/main_window.py`

## 1. 背景与目标

点击「查询」后，主线程同步执行全量 `filter` 并用 `QTableWidgetItem` 逐格填表。匹配行数到数千～十万时，界面长时间不处理事件，表现为无响应甚至 Windows「未响应」。

**成功标准**

1. 结果表每次最多展示 **200** 行；支持上一页 / 下一页浏览全部匹配结果
2. 全选、改状态、导出**仅作用于当前页**
3. 底部文案：`共 N 条，已选 M 条`——N = 本次查询总匹配数，M = 当前页选中数；页码另由翻页区展示
4. 查询（含翻页加载）进行中：相关按钮禁用，查询按钮文案为 **「查询中…」**，避免误点与误以为死机
5. 生成成功后的结果展示走同一套分页，避免一次画出上千行

**规模假设**：产线库可达数万～约十万行；本机 SQLite + 每页 200 行即可接受，不做后台线程与 keyset 分页。

## 2. 方案选型

采用 **SQL `LIMIT`/`OFFSET` 分页 + 保留 `QTableWidget`**：

| 方案 | 结论 |
|------|------|
| OFFSET 分页 + `QTableWidget` | **采用**：改动面小，与「仅当前页操作」一致 |
| 分页 + `QAbstractTableModel` | 不做：每页仅 200 行时收益有限、测试改动大 |
| 滚动按需加载 | 不做：与「当前页全选/导出」难对齐 |

查询仍在主线程执行；进入查询中态后先 `QApplication.processEvents()` 再跑 SQL/填表，保证「查询中…」可见。不做 `QThread`（避免 SQLite 跨线程连接）；若日后仍卡顿再单独立项。

## 3. 数据层

### 3.1 `filter_serials`

- 增加可选参数 `limit: int | None = None`、`offset: int | None = None`
- 未传 `limit` 时行为与现网一致（返回全部），供测试与其它调用兼容
- 传入时追加 `LIMIT ? OFFSET ?`；`offset` 缺省为 `0`
- `limit < 0` 或 `offset < 0` → `ValueError`
- `WHERE` / `ORDER BY created_at DESC, sn` 不变

### 3.2 `count_serials`

- 新增：与 `filter_serials` **同一套**筛选条件构建，执行 `SELECT COUNT(*) ...`，返回 `int`
- 不排序、不分页

### 3.3 `SnService`

- `filter(..., limit=..., offset=...)` 透传
- `count(**criteria) -> int` 调用 `count_serials`

## 4. 主界面状态与流程

### 4.1 状态字段

- `_query_criteria`：上次成功查询的条件（翻页复用）
- `_total_count`：总匹配数 N
- `_page`：当前页，**从 1 起**
- `_page_size = 200`（常量，本迭代不可调）
- `_rows`：仅当前页数据

总页数：`P = max(1, ceil(N / 200))`；`N = 0` 时视为 `P = 1`。

### 4.2 点「查询」

1. `_set_query_busy(True)`：查询按钮文案 →「查询中…」；禁用查询、生成、主数据、全选、改状态、导出、上一页、下一页
2. `QApplication.processEvents()`
3. 用当前筛选构建 criteria；`N = count(...)`；`page = 1`；`rows = filter(..., limit=200, offset=0)`
4. 填充表；更新数量标签与翻页控件
5. `_set_query_busy(False)`：文案恢复「查询」；按规则恢复启用

筛选控件在查询中可继续改；新条件须再次点「查询」才生效（不取消进行中的加载）。

### 4.3 翻页

- 底部行顺序：`_count_label` | 翻页区（上一页、`第 p / P 页`、下一页）| stretch | 改状态 | 导出
- 上一页 / 下一页：busy 态同上；条件用 `_query_criteria`；`offset = (page - 1) * 200`；换页后**清空选中**
- `N = 0` 或仅一页：两按钮禁用；文案 `第 1 / 1 页`
- 首页禁用上一页；末页禁用下一页

### 4.4 生成成功后

- 结果集为刚生成的这批 SN（与现行为一致）
- 若条数 > 200：分页展示；默认第 1 页；`selectAll` **仅选中当前页**
- `_total_count` = 本批条数；`generate` 已返回完整 list，主窗口保留该完整列表，用**内存切片**填当前页（不为此再查库）
- 该模式下翻页只做切片填表，**不**进入「查询中…」（耗时可忽略）
- 本迭代**不强制**「生成中…」busy 态；但生成后的填表必须走分页
- 之后若用户再点「查询」，切回 DB 分页模式，丢弃内存完整列表，按筛选条件重新 count/filter

### 4.5 其它既有行为

- **北京时间**勾选：只重绘当前页已加载行，不重新查库、不改页码
- **改状态 / 导出**成功后：按 SN 刷新当前页可见行；N 与页码不变。若因状态筛选导致本页逻辑上应变空——本迭代不自动跳页，用户再点「查询」即可
- 改筛选后未点「查询」：表与页码仍为上一次成功查询结果

## 5. 错误处理

- 查询 / 翻页抛错：结束 busy 态；`QMessageBox` 提示；尽量保留上一屏有效数据，不静默清空整表

## 6. 测试要点

- `count_serials` 与同条件 `filter` 行数一致；`limit`/`offset` 切片正确；负值 `ValueError`
- GUI：每页 ≤200；第 2 页内容正确；全选只选本页；`共 N` 为总数、`已选 M` 为本页选中
- 查询中：文案「查询中…」且约定按钮禁用（可通过状态辅助方法或短时桩断言）
- 回归：状态色、北京时间、结果计数等既有测试适配「N=总数」与分页 API

## 7. 明确不做（本迭代）

- 跨页全选 / 导出 / 改状态
- 可调页大小
- 后台线程查询
- keyset 分页、虚拟滚动
- 强制「生成中…」busy 态（可选，非必须）
