# 结果表底部数量统计设计

日期：2026-07-31  
状态：已确认  
关联：`src/sn_manager/gui/main_window.py`

## 1. 背景与目标

结果表下方右侧已有「改状态」「导出」；操作员在查询或多选后，需要一眼看到当前结果条数与选中条数，而不必数行。

**成功标准**

1. 结果表下方左侧、与「导出」同一行，显示 `共 N 条，已选 M 条`
2. 启动及空表时始终显示 `共 0 条，已选 0 条`
3. N = 当前结果表行数；M = 当前选中行数；查询、生成、选中/全选变化时即时更新

## 2. 方案

采用 **底部行左侧单个 `QLabel`**：

- 在现有 `bottom_row`（`QHBoxLayout`）中，于 `addStretch()` 之前插入 `_count_label`
- 用 `_update_count_label` 统一刷新文案；可在 `_update_action_buttons` 中一并调用（该函数已接 `itemSelectionChanged`）
- `_populate_table` 结束后也刷新一次，保证查询/生成后 N 正确（选中清零或恢复后 M 由 selection 信号或同次刷新覆盖）

## 3. 改动点

### 3.1 布局

`_build_results_panel` 底部行顺序：

1. `_count_label`（`QLabel`，初始文案 `共 0 条，已选 0 条`）
2. `addStretch()`
3. 「改状态」「导出」

不改顶部「结果表 / 北京时间 / 全选」行。

### 3.2 刷新逻辑

```text
文案 = f"共 {self._table.rowCount()} 条，已选 {len(self._selected_sns())} 条"
```

触发：

| 时机 | 说明 |
|------|------|
| 建窗完成后 | 初始 0 / 0 |
| `_populate_table` | 查询、生成、北京时间重绘等换表后 |
| `itemSelectionChanged`（经 `_update_action_buttons`） | 单击、多选、全选、取消选中 |

### 3.3 测试

新增或扩展 GUI 测试：建窗文案为 `共 0 条，已选 0 条`；填充若干行并选中后文案与 N/M 一致。

## 4. 非目标

- 不改「改状态」「导出」启用条件与其它业务逻辑
- 不引入分页、状态栏（`QStatusBar`）或额外主题样式
- 不拆成两个独立标签（除非后续有样式需求）

## 5. 验证

- 启动：`共 0 条，已选 0 条`，位于导出按钮左侧同一行
- 查询得 N 行、未选中：`共 N 条，已选 0 条`
- 选 M 行 / 全选：M 正确；取消选中回到 0
- 生成替换表后 N/M 与表一致
